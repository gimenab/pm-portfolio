PM-AI-Workflow: Automating the Busywork of Project Management

A system of AI skills and subagents that handles the repeatable, structured work of project management — ticket intake, sprint reporting, stakeholder updates — so strategic time stays protected.

Role Project Manager
Users Product & Agile Team
Approach Agentic Automation
Status In progress — first skills validated
01 /

The Problem & Value Proposition

The Operational Tax

PMs lose a large share of their week to repeatable admin work — formatting tickets, assembling reports, chasing updates, drafting scope documents and more — time that competes directly with strategy, discovery, and prioritization.

PM-AI-Workflow's Value Proposition

Structured, repeatable project management work shouldn't compete with strategic thinking for the same hours.

Read more

A system of AI skills and subagents takes over the high-volume, structured parts of the role — from ticket intake to scope analysis — and frees time for the judgment calls only a project manager can make. Every skill is plain Markdown that any AI agent able to read the repo can follow, and it is auditable in git. The SOW intake prompt was validated on Claude, ChatGPT and Gemini.

02 /

How It Works

Every skill and subagent in the system follows the same three-step flow, turning unstructured input into standardized, ready-to-use output:

RAW INPUT A problem description or live sprint data
AI SKILL / SUBAGENT Guided intake or autonomous analysis
STANDARDIZED OUTPUT A complete Jira ticket or a ready-to-share report
Example — SOW: from brief to Discovery

A founder brief goes through four skills. First, sow-drafting turns it into a Statement of Work, and sow-intake-analysis reads that SOW critically and flags what is missing:

founder-brief.pdf

> “If a user turns everyday functional actions into recovered, protected time, they will be more likely to spend real time on activities that bring them well-being.”

Excerpt from the original brief, translated from Spanish. It has no timeline, budget, stakeholders or acceptance criteria.

sow-intake-analysis — 31 gaps flagged
No sponsor, lead or decision authority → Who decides on scope changes and approves the MVP?
Timeline, budget and resourcing are all absent → What are the deadline, budget and available team?
Platform → Which platform(s) must the MVP support?

+ 28 more, each with why it matters and a clarifying question.

After the alignment meeting decides those gaps, the updated SOW goes through the two skills that prepare Discovery:

sow-discovery-prep — SOW v2 → Discovery plan 5 research questions, each with method, evidence and the decision it feeds → e.g. Who feels they have no time for themselves?
discovery-user-flow — core loop → what-if questions The loop drawn step by step, with 24 questions for the client to decide → e.g. What if the user marks a task by mistake?

Example — Structured Ticket Intake

Two rough notes from the Treasure Time backlog go through the ticket skills. Each note is shown as written, next to an excerpt of the draft the skill produced. Both ran in draft mode, without a Jira connection, so nothing was created in Jira.

raw-note.txt

> “When accessing the daily tasks, I need to see the pre-loaded tasks for the day (up to a maximum of three); there may also be a fourth task that I added myself earlier, marked as "difficult." When I mark a task as complete, I want the earned minutes to be added automatically, without having to press any extra buttons.”

work-item-user-story — 2 stories, 13 criteria
US 1, title USER STORY [DAILY TASKS] As a user I want to see today’s pre-loaded tasks and my own difficult task so that I know what I have to do today
US 2, criterion 01 · Complete a task, minutes credited Given a task in my list is pending, when I mark it as complete, then its fixed minutes value is added to my bank of minutes automatically, with no extra button or confirmation.
US 2, criterion 05 · No double credit (proposed) Given a task is already completed, when I trigger completion again or reload the screen, then the minutes are not added a second time.

The note mixed two needs, so the skill split it into two stories.

Also drafted: assumptions, story points, labels and priority. Whatever the skill inferred, and you did not say, is marked “(proposed)”.

raw-note.txt

> “Create a task to generate 10 tasks across the categories of health, home, and work, and assign minutes to each that will be added to the time bank upon completion.”

work-item-task — task draft
Title [DAILY TASKS] Create 10 tasks across health, home and work with bank minutes (proposed)
Objective Provide a ready-to-use catalog of tasks, each with a fixed time bank reward.
Done when (proposed) There are exactly 10 tasks and all three categories are represented. Every task has a fixed minutes value. Minutes roughly reflect effort, so longer or harder tasks earn more.

Also drafted: context, scope with what is excluded, estimate, priority and labels.

SOW: from brief to charter

Six skills that take a Statement of Work from the client brief, through Discovery, to a signed project charter.

Read more

Seven skills that take a Statement of Work from the client brief through Discovery to the project charter: one drafts a formal SOW from an unstructured brief, one critically reads it and flags every gap — timeline, budget, stakeholders, acceptance criteria —, one turns those gaps into the kickoff decision log, where “we will estimate it” is never a yes, and one turns the SOW agreed at the alignment meeting into a Discovery plan: a persona framed as a hypothesis, the MVP feature matrix and an agenda built from the open questions. During Discovery, a fourth skill walks the core loop with the client and turns each “what happens if...?” into a decision with an owner, before any user story is written. A fifth brings the findings and decisions together into a traceable list of changes for the next SOW, asking the client only what is still open. A sixth writes the project charter that authorizes the build, with SMART goals written as outcomes and how each is measured; before release it was reviewed by ChatGPT and Gemini and run blind against a charter written by hand. The reading prompt was validated across three different LLMs for consistency, not just tuned for one.

Analysis: stakeholders and gaps

Two skills that turn what stakeholders said into a power / interest map and a gap analysis traced to the requirements.

Read more

Both skills come from the wildfire case, where the map and the gap analysis were first built by hand. The stakeholder skill works only from what was said or agreed; the PM places each stakeholder, high or low, never medium, and every placement cites its source. A stakeholder with high power who was never consulted becomes an open item. The gap skill puts today, should be and the requirements that cover each gap side by side, and checks both directions: a gap with no requirement and a requirement with no gap both go to the PM. Before release, separate agents ran each skill blind on Treasure Time, twice. The first run showed the rules assumed several stakeholders and real meetings, and it found a real contradiction: the SOW still allowed taking more than the balance after the founder capped it. The fixes were tested again in a second run.

Planning: backlog, risks and RACI

Four skills that turn an authorized phase into a plan: the backlog and build order, the risk register, the risk management plan and who does what.

Read more

The backlog skill traces every item to an acceptance criterion and writes the cut rule before the build starts; during the build it records what really happened and which documents each decision must reach. The risk register judges probability from facts, never from invented numbers, gives each risk one owner and a response with its warning sign, and tracks the risks that fire. The risk management plan follows the course template and adds what PMBOK asks for: tolerance, roles, funding, scales written for this project, and who is told what. The RACI gives each activity one decider and at least one doer, and shows joint and outside sign-offs. All four come from the Treasure Time plan, written by hand first, and each was run blind on the wildfire case before release: a project with a funder, a contractor team and months of work, which found the rules that only fit a one-person build.

sow-discovery-prep v1.0.1

v1.0.0 · 2026-10-04

discovery-user-flow v1.1.1

v1.1.0 · 2026-10-08

  • Added: the flow diagram uses the standard flowchart shapes of ISO 5807 / ANSI: start, input/output, process, decision, manual step outside the product, stored data. Rules that change the path are drawn as decisions.
  • Why: standard notation lets any developer, designer or stakeholder read the flow without confusion. Redrawing Treasure Time with it surfaced a decision the plain boxes hid: the day bonus only applies if all of the day’s tasks are done.

v1.0.0 · 2026-10-08

  • Added: first version. Two stages: a prep (the happy path taken from the SOW, and what-if questions for each step, written through fixed lenses such as mistakes, limits, time, interruptions and rules that collide) and the workflow session, where the project manager asks and the client decides. Output: happy path, flow diagram, what-if log with priority, decision, owner and status, and conflicts with the SOW.

discovery-synthesis v1.0.0

v1.0.0 · 2026-10-16

  • Added: first version. Two stages: a prep (findings grouped into themes, an insight per theme, every SOW change with its origin and status, an assumption log, a hypothesis statement and a traceability map) and the synthesis session, where the client decides only the open rows. Example • work-item-user-story

Raw note → 2 user stories

The note mixed two needs, so the skill split it into two stories. The complete draft the skill produced, as generated. Nothing was created in Jira.

User Stories: Daily Tasks and Bank of Minutes

Status: Draft. Nothing has been created in Jira. Items marked (proposed) are inferred, not stated by the requester.

US 1: View daily tasks

Title

USER STORY [DAILY TASKS] As a user I want to see today's pre-loaded tasks and my own difficult task so that I know what I have to do today

Description

As a user, I want to see the day's pre-loaded tasks (up to three) together with the difficult task I chose earlier, if any, so that I know exactly what I have to do today.

ID Criterion Given When Then
01 View pre-loaded tasks Tasks are pre-loaded for today I open the daily tasks I see the pre-loaded tasks for the day, never more than three
02 Fewer than three tasks Fewer than three tasks are pre-loaded for today I open the daily tasks I see only the tasks that exist, with no empty placeholders (proposed)
03 View my difficult task I chose one task for today and marked it "difficult" I open the daily tasks I see it as an additional task after the pre-loaded ones, so up to four tasks in total
04 No difficult task I have not chosen a difficult task for today I open the daily tasks I see only the pre-loaded tasks
05 Difficult task is distinguishable My difficult task is in the list I open the daily tasks I can tell it apart from the pre-loaded tasks (proposed)
06 Load failure The tasks cannot be loaded I open the daily tasks I see an error message and no partial or incorrect list (proposed)

Assumptions

  • The system pre-loads the day's tasks (up to three) before the user opens the screen. How they are selected is out of scope.
  • The user can choose one difficult task per day, regardless of category. This limit is enforced by the existing flow, so the screen never shows more than one.
  • The maximum of three applies to pre-loaded tasks only. The difficult task is an additional fourth item.
  • Creating or editing tasks and the "difficult" marking flow are out of scope.

Additional fields

  • Story Points: 2 (proposed). Estimated Points auto-populates with the same value.
  • Labels: daily-tasks, task-list (proposed)
  • Priority: Medium (proposed)
  • Sprint: Backlog
  • Assignee: Unassigned

US 2: Automatic minutes on task completion

Title

USER STORY [DAILY TASKS] As a user I want the earned minutes to be added to or removed from my bank of minutes automatically when I mark or unmark a task as complete so that I don't need extra steps and my balance is always correct

Description

As a user, I want the minutes of a task to be added to my bank of minutes automatically when I mark it as complete, and subtracted if I unmark it, so that I don't need extra buttons and my balance stays correct even if I mark a task by mistake.

ID Criterion Given When Then
01 Complete a task, minutes credited A task in my list is pending I mark it as complete Its fixed minutes value is added to my bank of minutes automatically, with no extra button or confirmation
02 Complete the difficult task My difficult task is pending I mark it as complete Its fixed minutes value is added to my bank of minutes automatically, the same as any other task
03 Visible feedback I just completed a task The minutes are added I see the task as completed and my updated bank of minutes (proposed)
04 Unmark by mistake, minutes subtracted A task is completed and its minutes were added I unmark it as complete The same minutes are subtracted from my bank of minutes automatically, and the task returns to pending
05 No double credit A task is already completed I trigger completion again or reload the screen The minutes are not added a second time (proposed)
06 Repeated toggling stays consistent I mark and unmark the same task several times I end on either state The bank of minutes equals the balance before the task, plus the task's minutes only if it ends as completed (proposed)
07 Operation failure I mark or unmark a task but the change cannot be saved The operation fails I see an error message, and the task state and bank of minutes remain consistent with each other (proposed)

Assumptions

  • Each task has a fixed minutes value, and the rule that defines it already exists. This US does not change it.
  • The difficult task earns its minutes with the same fixed-value logic as other tasks, with no extra multiplier, unless its own value says otherwise.
  • The bank of minutes already exists as the user's balance. This US covers only crediting and debiting it on completion changes.
  • The amount subtracted on unmarking is exactly the amount that was credited, so the balance can't go below what it was before the task.
  • The rules for using or redeeming minutes are out of scope.

Additional fields

  • Story Points: 3 (proposed). Estimated Points auto-populates with the same value.
  • Labels: daily-tasks, minutes-bank (proposed)
  • Priority: Medium (proposed)
  • Sprint: Backlog
  • Assignee: Unassigned

Open point

  • The difficult task is assumed to have its own fixed value like any other task, not a bonus. If it earns more, criterion 02 in US 2 needs a specific rule.

Type: Task
Platform: Jira (assumed)
